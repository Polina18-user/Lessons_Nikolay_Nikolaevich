#### Замечание 1
ENUM (перечисление) - это столбец, который может принимать значение из списка допустимых значений, явно перечисленных в спецификации столбца в момент создания таблицы.
Каждая величина из допустимы имеет индекс:

1. Значение из списка допустимых величин, определенных при создании таблицы нумеруются, начиная с 1.
2. Индекс пустой ошибочной строки - 0. Это означает что вы можете использовать следующий SELECT для того, чтобы найти записи, в которые были вставлены некорректные значения ENUM:
3. Индекс значения NULL - NULL.

#### Замечание 2 
1. TIMESTAMP — это тип данных, который хранит дату и время (год, месяц, день, часы, минуты, секунды).
2. Формат хранения: YYYY-MM-DD HH:MM:SS (например, 2024-05-15 14:30:00)
3. TIMESTAMP — единственный тип в MySQL, который может автоматически заполняться и обновляться:

DEFAULT CURRENT_TIMESTAMP — при вставке новой строки автоматически ставит текущее время.
ON UPDATE CURRENT_TIMESTAMP — при изменении строки автоматически обновляет время на текущее.

#### Замечание 3
При выборе тех полей, которые могут быть NULL нужно учитывать:
1. Что они не являются обязательными для идентификации пользователя (в отличие от id name)
2. Могут быть неизвестны на момент регистрации
3. Содержат персонализированные данные, которые пользователь может не захотеть указывать.
Я считаю, что к таким полям относятся gender, bday, postal_code, rating

## Задание 8
```sql
CREATE TABLE `simpledb`.`resume` (
  `resumeid` INT NOT NULL AUTO_INCREMENT,
  `userid` INT NOT NULL,
  `title` VARCHAR(100) NOT NULL,
  `skills` TEXT NULL,
  `created` TIMESTAMP NULL DEFAULT CURRENT_TIMESTAMP(),
  PRIMARY KEY (`resumeid`),
  INDEX `userid_idx` (`userid` ASC) VISIBLE,
  CONSTRAINT `userid`
    FOREIGN KEY (`userid`)
    REFERENCES `simpledb`.`users` (`id`)
    ON DELETE CASCADE
    ON UPDATE CASCADE);
```
Поскольку для внешнего ключа задано правило ON DELETE CASCADE, при удалении пользователя из таблицы users СУБД автоматически удалит все связанные с ним резюме из таблицы resume.
Например, если удалить пользователя с id = 5, то все строки в resume, у которых userid = 5, будут удалены автоматически, без генерации ошибки.

Удаление резюме никак не затрагивает таблицу users, так как resume — дочерняя таблица, а users — родительская. Каскад работает только «вниз» по иерархии связей.

Поскольку задано ON UPDATE CASCADE, если по какой-то причине значение id пользователя в таблице users изменится, СУБД автоматически обновит соответствующее значение userid во всех связанных строках таблицы resume.
Ссылочная целостность сохраняется без ручного вмешательства.

На практике id обычно не меняется (это первичный ключ с AUTO_INCREMENT), но правило гарантирует корректность данных даже в таком сценарии.
